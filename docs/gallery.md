# ספריית הלמידה

האתר נמצא בתיקיית `learning-library/` בשורש הריפו ומתפרסם ב־Cloudflare בכתובת
[knowledge.davinci4744.com](https://knowledge.davinci4744.com/). קוד האתר וכלי היצירה
נשמרים ב־Git; התכנים לפרסום והקטלוג נשמרים ב־R2. האתר טוען את הקטלוג בזמן פתיחת
הגלריה. פרסום שיעור חדש אינו מחייב בנייה או פריסה מחדש של האתר.

## הרצה ובנייה

```sh
npm --prefix learning-library ci
npm --prefix learning-library start
npm --prefix learning-library run build
```

בניית האתר מעתיקה רק נכסי מותג ויוצרת קטלוג ריק לפיתוח מקומי. היא אינה סורקת את
`projects/`, אינה מרנדרת סרטונים ואינה צריכה Python או גישה ל־R2.
בייצור, ממשק הניהול המוגן ב־`/admin/` מעדכן את הקטלוג ישירות. ה־Worker מגיש את `/library/catalog.json` ואת קובצי השיעורים מתוך ה־bucket.
האתר הבנוי נמצא ב־`learning-library/output/site/`.

לתצוגה מקומית עם שיעור שהוכן מראש:

```sh
.venv/bin/python scripts/prepare_gallery.py --project my-training
LIBRARY_PREVIEW_DIR="$PWD/learning-library/output/content/library" npm --prefix learning-library start
```

אין להגדיר `LIBRARY_PREVIEW_DIR` בפריסת ייצור: התוכן מגיע שם מ־R2.
לבדיקת ה־Worker מקומית, בונים את האתר, מריצים `prepare:content` בתיקיית `cloudflare/`
ואז `npm run dev` באותה תיקייה. ברירת המחדל משתמשת באחסון R2 מקומי ומבודד.

## יצירה ופרסום תוכן

מורידים את מקורות השיעור מ־R2 באמצעות `scripts/project_store.py pull <id>`. המקורות המשוחזרים נשמרים מקומית ב־`projects/<id>/content.json`, ומוחרגים מ־Git. כותרות תצוגה, תיאורים,
קטגוריות וסימון `featured` או `unlisted` נשמרים ב־`projects/<id>/publication.json`.
קבצים חדשים ב־R2 אינם הופכים אוטומטית לכרטיס: כלי הפרסום מוסיף רשומה לקטלוג רק אחרי
שהקבצים הדרושים קיימים ונבדקו. אפשר לפרסם גם תכנים שנוצרו מחוץ לריפו, באמצעות חבילת
פרסום שתואמת למבנה `catalog.json`, `media/` ו־`exports/`.

אחרי יצירת סרטון, שומרים חבילת נגן מקומית לפרסום:

```sh
.venv/bin/python scripts/prepare_gallery.py \
  --publish-video my-training \
  --from projects/my-training/output/video/interactive \
  --publish-only
.venv/bin/python scripts/prepare_gallery.py --project my-training
.venv/bin/python scripts/publish_library.py --dry-run
.venv/bin/python scripts/publish_library.py
```

חבילות נגן נשמרות במטמון מקומי תחת `learning-library/output/published/`, שמוחרג מ־Git.
תוצרי הפרסום נוצרים ב־`learning-library/output/content/`.
יש לבדוק את התוכן, הווידאו והקריינות לפני הפרסום. שומרים גם גרסת מקורות באמצעות `scripts/project_store.py push <id>`; הוראות שחזור ב־[מדריך המקורות](project-sources.md). פרטי ההתקנה וההרשאות במדריך
[Cloudflare ו־R2](cloudflare.md).

כל פרסום מעלה גרסה חדשה, מאמת את הקבצים ומעדכן את הקטלוג בסיום. עדכון שיעור קיים
שומר את מזהה הפרויקט ואת הקישורים הישירים לגלריה. התקדמות מקומית בנגן נשמרת לפי
מזהי השיעור; חבילות SCORM עצמאיות כוללות את המדיה בתוך ZIP ומדווחות למערכת הלמידה.

## גלריות וקישורים

הגלריה הציבורית מציגה תכנים שאינם מסומנים `unlisted`. הנתיב `/team-library/` מציג
תכנים מסומנים, ואינו מקושר מתוך הגלריה הציבורית. זו הסתרה מתצוגה, ולא הגנת הרשאות:
הקטלוג ציבורי וכל מי שמחזיק בקישור יכול לצפות ולשתף.

קישור ישיר לשיעור נשאר בצורה `?item=<project-id>&view=deck` או `view=video`.
נגן הווידאו כולל פרקים, חיפוש בתמליל, שאלות ושמירת התקדמות. דיאלוג הייצוא מאפשר
להוריד חבילות SCORM למצגת ולסרטון, לפי הפורמטים הזמינים באותו שיעור.

לפרסום בקישור בלבד, ללא כרטיס באף גלריה, מגדירים ב־`publication.json`
את `"gallery": "none"` ואת `"unlisted": true`. הקישור הישיר נפתח מהנתיב הראשי
באמצעות `?item=<project-id>&view=deck`. הרשומה נשמרת בקטלוג כדי לאפשר קישור קבוע
וייצוא; ההסתרה מהגלריות אינה הגנת הרשאות.

## מבנה הקוד

- `learning-library/app/`: נתיבי הגלריות ומסמך HTML.
- `learning-library/src/`: הקטלוג, חיפוש וסינון, צפייה וייצוא.
- `learning-library/cloudflare/`: הגשת האתר ותוכן R2 והפניית הדומיין הישן.
- `scripts/prepare_gallery.py`: הכנת שיעורים שנבחרו במפורש.
- `scripts/publish_library.py`: העלאה, אימות ועדכון קטלוג ב־R2.
- `scripts/prepare-gallery.mjs`: נכסי האתר לפיתוח ולבנייה, ללא שיעורים.

בדיקות: `npm --prefix learning-library test`, בדיקות TypeScript ופורמט, בדיקות Worker
ובדיקות Python. הוראות פריסה מלאות מופיעות במדריך Cloudflare.

## גלריית לימודים

הנתיב `/study-library/` מציג חומרי לימוד לבית הספר. ברשומת השיעור ב־`projects/<id>/publication.json` מגדירים `"gallery": "study"`; כלי הפרסום שומר את הבחירה בקטלוג R2. התוכן אינו מופיע בגלריה הציבורית או בגלריית הקבוצה. הנתיב אינו מקושר מתוכן, ומסומן `noindex,nofollow`. קישורים ישירים ושאלות החזרה נשמרים כמו בשאר הגלריות.


## קטלוג משותף לאתר ולאדמין

הפורמט הקנוני של `library/catalog.json` הוא אובייקט בגרסה 1:

```json
{
  "schemaVersion": 1,
  "galleries": [
    { "id": "public", "name": "ספרייה ציבורית", "url": "/" },
    { "id": "none", "name": "בקישור בלבד", "url": "/" },
    { "id": "robotics", "name": "רובוטיקה", "url": "/training/robotics" }
  ],
  "items": []
}
```

האדמין מייצא ומייבא את אותו המסמך, כולל שדות מטא־דאטה נוספים. האתר קורא את השמות,
הקישורים ושיוך התכנים מתוכו בזמן הטעינה. תכנים וספריות מקטלוגים ישנים בפורמט מערך
עדיין נתמכים, עם ארבע ספריות ברירת המחדל ועם התנהגות `unlisted` המקורית.
הספריות `public` ו־`none` קבועות. ספריות אחרות יכולות לקבל מזהים ונתיבים חדשים;
מחיקה באדמין מעבירה את התכנים שלהן ל־`none`.

נתיבים מקומיים, כולל נתיבים מקוננים, נפתרים בזמן ריצה מתוך הקטלוג באמצעות ה־Worker
ואותו מסך ספרייה. אין צורך לייצר קובץ React לכל ספרייה. קישור מלא לכתובת חיצונית
נשאר קישור יוצא. פרמטר `gallery` מבדיל בין ספריות שבחרו באותו נתיב, ופרמטרי
`item` ו־`view` נשמרים לצפייה ישירה. ספריות שאינן ציבוריות אינן מתווספות לתצוגת
התכנים הציבורית.

אפשר להפנות את האתר לשרת האדמין המקומי באמצעות
`EXPO_PUBLIC_CATALOG_URL=http://127.0.0.1:4310/library/catalog.json`.
שרת האדמין חייב להיות מופעל עם `LIBRARY_DEV_ORIGIN=http://localhost:8082`,
והאתר עם `npm --prefix learning-library start -- --localhost --port 8082`.
ההרשאה הזו מאפשרת קריאת קטלוג בלבד. בסביבת ייצור הכתובת נשארת
`/library/catalog.json` שמוגשת מ־R2. האדמין שבייצור בכתובת `/admin/` שומר ישירות לקטלוג R2; האתר טוען את השינויים בפתיחה הבאה. פריסת קוד האתר נותרת פעולה נפרדת.

בהכנת חבילת תוכן אפשר להעביר `--catalog /path/to/catalog.json` כדי להשתמש בהגדרות
הספריות ובנתוני התכנים שנערכו באדמין. שני כלי הפרסום תומכים במסמך החדש ובמערך
הישן. פרסום חוזר מעדכן את קישורי המדיה של שיעור קיים ושומר את נתוני הקטלוג,
כולל שמות, פרקים, שיוך ספרייה, קישורי ספריות ומטא־דאטה. רשומת תוכן חדשה חייבת
להפנות לספרייה שכבר קיימת בקטלוג המשותף. קטלוג קודם נשמר בהיסטוריה וכללי בדיקת
התנגשויות והעלאת מדיה מאומתת נשמרים.
